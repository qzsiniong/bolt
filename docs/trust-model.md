# 信任模型

Bolt 在一个进程里跑三类由 JS 写成的代码：宿主自身的脚本功能、用户在脚本编辑器里写的脚本、以及 `extensions/` 目录里的第三方扩展插件。本文说明每一类默认拿到什么、边界画在哪里、以及哪些东西**没有**被隔离——先说清楚，再谈加固。

## 信任层级

| 层级 | 代码 | 默认权限 | 理由 |
| --- | --- | --- | --- |
| ① 宿主 | Rust 进程本身 | 完全信任 | 文件系统、网络、子进程、辅助功能与屏幕录制（macOS 系统级授权）都在它手里 |
| ② 用户脚本 | 脚本编辑器里的 `.js`/`.ts` | 全权 | 在编辑器里逐行可见，等同你自己写的代码 |
| ③ 插件脚本命令 | `extensions/<id>-v<ver>.js/` 里的脚本命令 | **按清单 `permissions` 声明授予，缺省全关** | 来源可能是别人写的，必须显式声明要动什么 |
| ④ 插件 UI 命令 | 同目录里的 `main.js`（gpui-shell） | 固定沙盒：读=插件目录、写=自己的数据目录；网络与子进程一律不授予；剪贴板由 `ui.capabilities.clipboard` 开关 | 渲染在宿主窗口里，能力由宿主按清单构建 |

## 插件权限（`extension.json` 的 `permissions`）

fail-closed：不写 `permissions` 就什么都拿不到。合法值（拼错的权限名会让插件加载失败，不会静默忽略）：

| 权限 | 解锁的 `bolt` 导出 | 风险 |
| --- | --- | --- |
| `fs` | `readFile` / `writeFile` / `listDir` | 全盘任意路径读写——SSH 私钥、浏览器配置都在范围内 |
| `net` | `fetch` | 任意网络请求（外发数据、下载） |
| `exec` | `exec` | `sh -c` 任意 shell 命令，等同拿到宿主全权 |
| `env` | `env` | 读进程环境变量——API key、token 常在这里 |
| `typeStr` | `typeStr` | 向焦点窗口注入键盘输入（需要辅助功能授权），可用来代你打字 |

不需要声明就能用的：`console`、定时器（`setTimeout` 等）、`sleep`、`exit`，以及全部交互 API（`confirm` / `pickPath` / `scanQr` / `requestFocus`）——它们要么无副作用，要么由用户当场在弹窗里做决定。

**被拒时的行为**：未声明的导出仍然出现在 `bolt` 模块里（`import` 不炸），但函数体是抛错桩，报错会点名缺哪个权限：

```
Error: 插件未声明权限 "fs"：请在 extension.json 的 permissions 中加入 "fs"
```

示例清单：

```json
{
  "id": "hello",
  "version": "1.0.0",
  "permissions": ["typeStr"],
  "commands": [{ "id": "sayHello", "title": "say hello" }]
}
```

注意 `permissions` 只约束**脚本命令**跑的 `bolt` 模块；UI 命令走 gpui-shell 的能力构建，不受它影响，剪贴板也由 `ui.capabilities.clipboard` 单独开关。

## 已有的隔离

- **每插件一个独立 QuickJS 运行时**（专用线程 + 常驻上下文）：全局对象、模块缓存、顶层状态互不可见；插件之间不能直接调用，只能通过宿主。
- **资源上限**：栈 8 MiB、堆 64 MiB、单命令 60 s 超时、入口加载 30 s 超时；卡死靠 QuickJS 中断打断，不会拖垮宿主。
- **私有数据目录**：`extensions-data/<id>/`，插件 storage 落在这里，互不覆盖。
- **UI 命令的固定沙盒**：gpui-shell 不给网络与子进程，读写范围限定在插件目录与自己的数据目录。
- **错误可见**：插件加载失败、命令报错、Error 级日志都会进 Console 面板并落盘 `bolt.log`。

## 没有的隔离（当前边界）

- **无 OS 级沙箱、无进程隔离**：QuickJS 与宿主同进程。`exec` 权限一旦声明，插件实际上拿到宿主全权；`fs` 权限是全盘的，不限定在插件目录内。
- **`extensions/` 目录即信任边界**：目录里的文件被当作你放进来的代码。任何能写这个目录的进程（另一个拿到 `fs` 权限的插件、恶意脚本、同步盘）都能替换插件内容——下次加载即生效。播种（首次启动复制内置扩展）只增不改，但没有防篡改机制。
- **`depends` 不做隔离**：依赖声明只参与 plux 的版本解析，不会限制被依赖插件的能力。
- **LSP 类型声明是全量的**：`bolt.d.ts` 按全部导出生成，不会按权限裁剪，被拒的 API 在 IDE 里依然可见。

## 给插件作者的基线

- 只声明真正用到的权限；用 `confirm` / `pickPath` 让用户显式参与，比静默读盘好。
- 别要求 `exec`，除非插件本质上就是干这个的——它是最高风险的一项。
- 把状态写进自己的 `extensions-data/<id>/`，别依赖插件目录可写（release 形态下它可能随仓库/分发物变动）。
